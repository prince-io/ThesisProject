# results/ — Measured Facts

## Purpose

Hold measured outcomes as facts: metrics, tables, and comparisons tied to a run ID.

## Ownership

- Authoritative for measured numbers.

## Local Contracts

- YAML front matter on every doc.
- Every number must trace to an experiment record and run ID.
- No interpretation or recommendations; keep those out.
- Prefer tables with explicit units and evaluation protocol.

## Work Guidance

- Run results are generated by `scripts/document_results.py` from `runs/` metrics.
- Baseline facts: `baseline.md` and `baseline-error-analysis.md`.
- Ablation facts: `ablation_cls_pw0.md`, `ablation_cls_pw0-error-analysis.md`, and `ablation-comparison.md`.
- V1 facts: `litevit_v1_p5.md` and `litevit_v1_p5-error-analysis.md`.
- The invalid V1 predecessor has no curated results doc; it is documented in `../findings/v1-invalid-run.md`.
- Gate-only facts: `weather_gate.md` and `weather_gate-error-analysis.md`.
- Cross-variant facts: `architecture-comparison.md`.
- A+B facts: `gate_p5.md`, `gate_p5-error-analysis.md`, and `gate-p5-comparison.md` (EXP-0005).
- Kitchen-sink results will be generated to `gate_edge_cbam.md` when `EXP-0006` completes.
- TTA facts: `weather-gate-tta.md`.
- Raw error-analysis data stays in `runs/eval/<run>/error_analysis/`.
- Curated figures live in `thesis/results/figures/`; full plots stay in `runs/`.
- VRAM values must be labeled as training-PyTorch, training-GPU-used, or inference.
