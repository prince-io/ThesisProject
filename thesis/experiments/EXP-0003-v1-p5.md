# EXP-0003 — V1 P5 LiteViT

## Objective

Test whether one identity-initialized LiteViT block after the YOLOv8n P5/SPPF layer,
before PAN/FPN, improves adverse-weather detection over the `EXP-0001` baseline.
This is the first ViT ablation in `ref/idea.md`, not the full LiteViT + weather-gate
model.

## Invalid predecessor

The first `litevit_v1_p5_seed42` run was invalid: Ultralytics rebuilt the detector
from `model.yaml` before training, which discarded the LiteViT wrapper. It trained
stock YOLOv8n and is retained only for audit. See
`thesis/findings/v1-invalid-run.md`.

The corrected run is `litevit_v1_p5_seed42_v2`; its trainer builds the wrapped model
inside `get_model()` and verifies the saved architecture after training.

A 10-epoch test after the FP32 fix (`litevit_v1_p5_test10`) completed with finite
losses and a correct 3,674,271-parameter block (epoch 10: val mAP50 0.4082,
mAP50-95 0.2367). The wrapper script failed after training before writing
`run_meta.json`/`vram.json`; fallback logging was added. A repeat test is pending.

## Scope

- Backbone, neck, and head are unchanged.
- One channel-preserving LiteViT block at P5 (20x20 tokens for a 640 input).
- P3/P4 remain CNN-only.
- No weather gate in V1.
- Same training and evaluation protocol as `EXP-0001`.

## Hypothesis and checks

- Initial model outputs should equal the baseline because the block is
  identity-initialized.
- Training should be stable at batch 4 with AMP; record VRAM.
- Saved `best.pt` must contain `FeatureWithBlock` at layer 9 and about 3.674 M
  parameters; `train.py` now fails otherwise.
- Compare val mAP50/mAP50-95 and per-condition, per-class, and per-size results
  against `EXP-0001`.
- Treat test as a secondary estimate; the test split has already been used by the
  Stage 2A baseline and ablation.
